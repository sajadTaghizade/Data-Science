• عنوان پروژه: سیستم توصیه‌گرِ سؤال‌های مشابهِ ++C در Stack Overflow
  (Semantic Similar-Question Recommender).
• هدف: برای هر سؤال ++C، نزدیک‌ترین سؤال‌های قبلی را پیشنهاد بده (برای حذف تکراری،
  ویجت «سؤالات مرتبط»، و هدایت کاربر به جوابِ موجود).
• «متغیر هدف»: چون توصیه‌گر است، خروجی مدل یک فهرستِ رتبه‌بندی‌شده از سؤال‌های نزدیک است؛
  همین فهرست‌ها در پایگاه‌داده ذخیره می‌شوند.
• دیتاست: ۲۶٬۱۶۲ سؤال ++C، ۵٬۵۷۲ تگ یکتا، بازه‌ی ۲۰۰۸ تا ۲۰۲۶، جمع‌آوری‌شده با کرالرِ
  خودمان از API رسمیِ Stack Exchange. هر سؤال: عنوان، متن HTML، تگ‌ها، تعداد
  بازدید/پاسخ/رأی، تاریخ.
• پروژه در ۳ فاز:

  ── فاز ۱ (جمع‌آوری داده) ──
  • اسکریپت crawl_stackoverflow.py؛ کرال بر اساس تگ c++؛ resumable (تکراری‌ها را رد
    می‌کند و ذخیره‌ی تدریجی)؛ بدون API key حدود ۳۰٬۰۰۰ سؤال در روز. دیتاست را از ۲٬۵۰۰
    اولیه به ۲۶٬۱۶۲ رساندیم.

  ── فاز ۲ (پایگاه‌داده، EDA، پایپلاین) ──
  • پایگاه‌داده‌ی SQLite نرمال‌شده با ۴ جدول: users, questions, tags, question_tags
    (رابطه‌ی چند‌به‌چند)، به‌همراه Foreign Key، Constraint و Index.
  • EDA + پاک‌سازیِ متنِ فنی که HTML را حذف می‌کند ولی توکن‌های ++C مثل std::vector و
    نشانگرِ بلوکِ کد را حفظ می‌کند.
  • پایپلاینِ بازتولیدپذیر pipeline.py + CI با GitHub Actions (ruff + pytest) +
    Dockerfile + مانیفستِ Kubernetes (Minikube Job).

  ── فاز ۳ (توسعه، ارزیابی و استقرار مدل) ──
  • تقسیمِ زمانی (temporal): train = 18,313 | validation = 3,000 | test = 3,000.
  • هفت مدلِ کاندید مقایسه شدند: title_word_tfidf، document_word_tfidf،
    char_wb_tfidf، lsa_document، bm25_document (خودمان پیاده کردیم)،
    document_prf (بسط کوئریِ Rocchio)، و hybrid (ترکیب وزن‌دار).
  • انتخاب با اعتبارسنجی متقاطعِ ۵-تایی روی nDCG@10. BM25 تنظیم شد (k1=2.0, b=0.9).
  • تکنیک‌های ضدِ نشتی: تقسیم زمانی، fit فقط روی train، انتخاب با CV، ارزیابیِ تست فقط
    یک‌بار.
  • دو پایپلاینِ جدا: train_pipeline.py و predict_pipeline.py (و run_pipeline.py برای
    اجرای هر دو). خروجی: ۳۰٬۰۰۰ توصیه در جدولِ recommendations در دیتابیس.
  • ثبتِ آزمایش‌ها با MLflow. بهبودها: تنظیم BM25، مدل PRF، متریک graded (gnDCG)،
    بازچینشِ MMR برای تنوع، مطالعه‌ی ablation، تحلیل خطا، و یک CLIِ تعاملی.
  • یافته‌ی ablation: مدلِ char n-gram بیشترین سهم را در هیبرید دارد.

• نتیجه‌ی انتخابِ مدل (CV nDCG@10 روی validation) — برای نمودار میله‌ای افقی:
    hybrid = 0.759  (برنده، با رنگ Accent)
    char_wb_tfidf = 0.739
    bm25_document = 0.726
    lsa_document = 0.705
    document_prf = 0.681
    document_word_tfidf = 0.676
    title_word_tfidf = 0.376

• نتیجه روی تستِ دیده‌نشده (جدول):
    Hit@5 = 0.836 | Hit@10 = 0.893 | Hit@20 = 0.931
    MRR@10 = 0.710 | nDCG@10 = 0.559 | Coverage = 95.5%

• مقایسه با بیس‌لاین (نمودار میله‌ایِ گروهی روی Hit@10):
    مدل هیبرید = 0.893 | بیس‌لاین تصادفی = 0.376 | بیس‌لاین محبوبیت = 0.105

• دیدِ کسب‌وکار: حذف سؤال تکراری، ویجت «سؤالات مرتبط»، هدایت به جوابِ موجود.
• محدودیت‌ها: برچسبِ ضعیفِ ارتباط (اشتراک تگ)؛ مدل‌های لغوی روی کلماتِ چندمعنایی مثل
  «queue» گاهی اشتباه می‌کنند؛ بدونِ امبدینگِ عصبی.
• کارهای آینده: افزودن مدلِ امبدینگِ عصبی، دیتاستِ بزرگ‌تر، بازخوردِ واقعیِ کاربر،
